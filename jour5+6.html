2. AudioContext : l'outil de base

2.1 — À quoi sert un AudioContext ?

Tout code audio sur le Web commence par une seule ligne : 

const audioCtx = new AudioContext();

Cet objet est le point d'entrée de toute opération audio. Sans lui, rien ne fonctionne. Il gère :

  • l'horloge audio ;
  • la fréquence d'échantillonnage ;
  • tous les nœuds (oscillateurs, gains, filtres).

2.2 — Le cycle de vie : 4 états

Un AudioContext a un état qu'on peut consulter :

ÉtatSignification
"suspended"Créé mais pas démarré (ou mis en pause)
"running"En cours d'exécution, le son peut circuler
"closed"Fermé définitivement, plus utilisable
"interrupted"Interrompu par le système (mobile, appel entrant)

2.3 — Créer

const audioCtx = new AudioContext();

À la création, l'état est "suspended". Le son ne circule pas encore.

2.4 — Démarrer / Reprendre

await audioCtx.resume();

Passe de "suspended" à "running". Doit être appelé après une action utilisateur (clic, touche), sinon le navigateur bloque.

2.5 — Suspendre (pause)

await audioCtx.suspend();

Passe de "running" à "suspended". Le son est mis en pause, mais le contexte reste utilisable.

2.6 — Vérifier l'état

console.log(audioCtx.state);   // "suspended" | "running" | "closed"

2.7 — Fermer

await audioCtx.close();

Passe à "closed". Le contexte est définitivement libéré. On ne peut plus l'utiliser. Pour rejouer, il faut en créer un nouveau.

2.8 — Bac à sable : tester le cycle de vie

Cliquez sur les boutons pour voir l'état changer en direct. C'est la seule façon de comprendre le cycle de vie.

AudioContext — cycle de vie

État : (aucun contexte)

Le code correspondant à chaque bouton est celui montré dans les sections 2.3 à 2.7. Le bouton « Créer » instancie un AudioContext ; « Démarrer » appelle resume() ; « Pause » appelle suspend() ; « Fermer » appelle close().

2.9 — Le graphe audio : structure de base

Un AudioContext ne produit rien tout seul. Il faut lui brancher des nœuds. La structure minimale est : 

source → traitement → destination
  • Source : produit un signal (oscillateur, fichier audio, micro…).
  • Traitement : transforme le signal (gain, filtre, délai…).
  • Destination : audioCtx.destination, la sortie vers les haut-parleurs.

2.10 — Premier son : un oscillateur et un gain

// 1. Le contexte
const audioCtx = new AudioContext();

// 2. Les nœuds
const oscillateur = audioCtx.createOscillator();
const gain = audioCtx.createGain();

// 3. Le gain (volume initial)
gain.gain.value = 0.3;

// 4. Les connexions
oscillateur.connect(gain);
gain.connect(audioCtx.destination);

// 5. Le démarrage
oscillateur.start();

Pour arrêter :

oscillateur.stop();

2.11 — L'horloge du contexte : currentTime

audioCtx.currentTime est le nombre de secondes écoulées depuis la création du contexte. Il avance en temps réel, dès que l'état est "running". 

console.log(audioCtx.currentTime);
// 0 au démarrage, puis 0.001, 0.002, 0.003…

C'est la référence temporelle de tout ce qu'on programme. Pour dire « dans 1 seconde », on écrit : 

const t = audioCtx.currentTime + 1;

2.12 — Démarrer et arrêter à un instant précis

start() et stop() acceptent un argument optionnel : un instant absolu (en secondes) mesuré sur l'horloge du contexte. 

const audioCtx = new AudioContext();

const osc = audioCtx.createOscillator();
osc.connect(audioCtx.destination);

const maintenant = audioCtx.currentTime;
osc.start(maintenant);            // démarre maintenant
osc.stop(maintenant + 0.5);       // arrête dans 500 ms

Règles :

  • Le temps est absolu, pas une durée.
  • Un OscillatorNode ne peut être démarré qu'une fois.
  • Si stop() est déjà appelé, il faut créer un nouvel oscillateur pour rejouer.
Pourquoi pas setTimeout ?

setTimeout(() => osc.stop(), 500) fonctionne, mais avec une précision de quelques millisecondes seulement. La méthode osc.stop(t) est précise à l'échantillon près, et programmée à l'avance. C'est la méthode professionnelle.

2.13 — Deux façons de régler un paramètre

Les paramètres audio (frequency, gain, …) sont des AudioParam. On peut les régler de deux façons.

Méthode 1 — Immédiatement, avec .value

// audioCtx, osc, gain supposés déjà créés
osc.frequency.value = 440;   // prend effet tout de suite
gain.gain.value = 0.3;

Méthode 2 — Planifié dans le temps, avec les méthodes

// audioCtx, gain supposés déjà créés
const maintenant = audioCtx.currentTime;

gain.gain.setValueAtTime(0, maintenant);
gain.gain.linearRampToValueAtTime(0.5, maintenant + 0.1);
gain.gain.exponentialRampToValueAtTime(0.001, maintenant + 0.5);
MéthodeEffet
setValueAtTime(v, t)Valeur fixe à l'instant t
linearRampToValueAtTime(v, t)Rampe linéaire jusqu'à v à l'instant t
exponentialRampToValueAtTime(v, t)Rampe exponentielle jusqu'à v à l'instant t
cancelScheduledValues(t)Annule tout ce qui est planifié à partir de t
Piège — exponentialRampToValueAtTime et zéro

exponentialRampToValueAtTime ne peut pas viser 0 (erreur native). Pour éteindre un son, on vise une valeur très petite, comme 0.0001, puis on arrête le nœud avec stop().

2.14 — Exemple complet avec durée

Un seul exemple qui combine tout : un La4 de 500 ms, avec une attaque rapide et une extinction douce. Sans setTimeout. 

// 1. Le contexte
const audioCtx = new AudioContext();

// 2. Les nœuds
const osc = audioCtx.createOscillator();
const gain = audioCtx.createGain();

// 3. Le gain initial à 0 (on le montera avec l'enveloppe)
gain.gain.value = 0;

// 4. Les connexions
osc.connect(gain);
gain.connect(audioCtx.destination);

// 5. Programmation de la note
const maintenant = audioCtx.currentTime;

osc.frequency.value = 440;                                  // La4
gain.gain.setValueAtTime(0, maintenant);                    // départ à 0
gain.gain.linearRampToValueAtTime(0.3, maintenant + 0.02);  // attaque (20 ms)
gain.gain.linearRampToValueAtTime(0, maintenant + 0.5);     // extinction

osc.start(maintenant);
osc.stop(maintenant + 0.5);

Tout est programmé à l'avance. L'oscillateur démarre et s'arrête aux instants voulus, le gain suit l'enveloppe. C'est la façon propre.

2.15 — Les 5 erreurs courantes

Erreur 1 — Oublier resume() 
const audioCtx = new AudioContext();
const osc = audioCtx.createOscillator();
osc.connect(audioCtx.destination);
osc.start();
// ❌ Rien ne se passe : le contexte est "suspended".

Correction : appeler await audioCtx.resume() après un clic utilisateur.

Erreur 2 — Appeler resume() sans action utilisateur 
const audioCtx = new AudioContext();
await audioCtx.resume();
// ❌ Le navigateur bloque : pas de geste utilisateur.

Correction : déclencher resume() depuis un gestionnaire d'événement (click, keydown).

Erreur 3 — Redémarrer un oscillateur déjà arrêté 
osc.start();
osc.stop();
osc.start();
// ❌ Un OscillatorNode ne peut être démarré qu'UNE fois.

Correction : créer un nouvel oscillateur à chaque note.

Erreur 4 — Oublier connect(destination) 
const osc = audioCtx.createOscillator();
osc.start();
// ❌ Aucun son : l'oscillateur n'est connecté à rien.

Correction : osc.connect(audioCtx.destination).

Erreur 5 — Confondre suspend() et stop()
  • audioCtx.suspend() : met tout le contexte en pause. Réversible avec resume().
  • osc.stop() : arrête cet oscillateur. Irréversible.
À retenir :

Tous les exemples des sections suivantes supposent que audioCtx existe et est démarré (voir section 2). Une fois cette base maîtrisée, on peut brancher n'importe quel nœud.

3. Nature physique du son

Un son est une variation de pression qui se propage dans un milieu matériel (air, eau, solide). Un haut-parleur produit cette variation en faisant vibrer une membrane ; notre oreille la perçoit comme un son.

Avant d'être une « note », un son est un signal : une fonction du temps. On peut donc l'écrire comme n'importe quelle fonction périodique.

3.1 — Le son comme fonction du temps

Un signal sinusoïdal pur s'écrit en JavaScript :

// Pression à l'instant t (en secondes)
function pression(t, amplitude, frequence) {
    return amplitude * Math.sin(2 * Math.PI * frequence * t);
}

Trois paramètres, rien de plus :

ParamètreRôleUnité
amplitudeIntensité du signal0 → 1
frequenceNombre de cycles par secondeHz
tInstant considéréseconde

La période est la durée d'un cycle :

const periode = frequence => 1 / frequence;   // en secondes

periode(440);   // 0.00227... s  →  2,27 ms
periode(880);   // 0.00114... s  →  1,14 ms

Doubler la fréquence, c'est diviser la période par 2. C'est tout. Le reste, c'est de la perception.

Schéma 1 — Sinusoïde et période

Une sinusoïde : la période T est la durée d'un cycle complet. La fréquence est l'inverse : f = 1 / T.

3.2 — Pourquoi l'oreille traduit la fréquence en « hauteur »

L'oreille ne mesure pas la fréquence : elle compte les cycles. Plus la membrane vibre vite, plus le cerveau perçoit un son aigu.

FréquencePériodePerception
100 Hz10 msgrave
440 Hz2,27 msmédium
4 000 Hz0,25 msaigu

À amplitude égale, la seule chose qui change entre grave et aigu, c'est frequence. Ni l'amplitude, ni la forme d'onde.

Schéma 2 — Deux fréquences comparées

Sur la même durée, 880 Hz produit quatre fois plus de cycles que 220 Hz. La hauteur perçue est directement liée à ce nombre de cycles par seconde.

3.3 — L'octave : pourquoi ×2 donne « la même note »

Un son réel n'est pas une sinusoïde pure. Il contient une fondamentale f et ses harmoniques 2f, 3f, 4f, 5f… 

const harmoniques = (f, n) =>
    Array.from({ length: n }, (_, i) => f * (i + 1));

harmoniques(261.63, 5);
// [261.63, 523.26, 784.89, 1046.52, 1308.15]   → Do4

harmoniques(523.25, 5);
// [523.25, 1046.5, 1569.75, 2093, 2616.25]     → Do5

Compare les deux listes : la 2e harmonique du Do4 est la fondamentale du Do5. La 3e du Do4 est la 2e du Do5. Etc.

Les harmoniques du Do5 sont exactement celles du Do4, décalées d'un rang. L'oreille reconnaît cette structure identique et conclut : même note, plus aigu. C'est ça, une octave. 

const estOctave = (f1, f2) => Math.abs(f2 / f1 - 2) < 1e-9;

estOctave(261.63, 523.25);   // true

Ce n'est pas une convention : c'est une propriété de la série harmonique. Doubler la fréquence reproduit la même structure harmonique, un cran plus haut.

Schéma 3 — Série harmonique

Une fondamentale et ses quatre premières harmoniques. La structure se répète : c'est ce que l'oreille reconnaît d'une octave à l'autre.

3.4 — La gamme tempérée : une formule, pas une table

Un développeur n'apprend pas une table de fréquences. Il écrit une formule. Entre deux notes voisines, le rapport de fréquence est constant. Il y a 12 demi-tons dans une octave : 

// n = nombre de demi-tons par rapport au La4 (n = 0)
const frequence = n => 440 * 2 ** (n / 12);

Pourquoi 12 demi-tons et seulement 7 noms de notes ?

En musique occidentale, on nomme 7 notes naturelles : Do, Ré, Mi, Fa, Sol, La, Si. Mais l'octave est découpée en 12 intervalles égaux, appelés demi-tons.

Les 5 demi-tons qui n'ont pas de nom « naturel » sont les notes altérées — les touches noires du piano. Elles portent un nom composé : # (dièse, +1 demi-ton) ou b (bémol, −1 demi-ton). Par exemple, La# et Sib désignent la même touche.

Voici les 12 demi-tons d'une octave, dans l'ordre :

nNoteTypeFréquence (Hz)
0Lablanche440,00
1La# / Sibnoire466,16
2Siblanche493,88
3Doblanche523,25
4Do# / Rébnoire554,37
5Réblanche587,33
6Ré# / Mibnoire622,25
7Miblanche659,26
8Fablanche698,46
9Fa# / Solbnoire739,99
10Solblanche783,99
11Sol# / Labnoire830,61
12Lablanche880,00

Pourquoi seulement 5 touches noires et pas 7 ? Parce que les 7 notes naturelles ne sont pas régulièrement espacées. Les intervalles sont : 

Do → Ré  : 2 demi-tons
Ré → Mi  : 2 demi-tons
Mi → Fa  : 1 demi-ton   ← pas de touche noire
Fa → Sol : 2 demi-tons
Sol → La : 2 demi-tons
La → Si  : 2 demi-tons
Si → Do  : 1 demi-ton   ← pas de touche noire

Total : 2+2+1+2+2+2+1 = 12 demi-tons. C'est ce 12 qu'on retrouve dans la formule.

Vérification avec la formule :

frequence(0);      // 440.00    → La4 (référence)
frequence(1);      // 466.16    → La#4
frequence(2);      // 493.88    → Si4
frequence(3);      // 523.25    → Do5
frequence(12);     // 880.00    → La5  (une octave au-dessus)
frequence(-12);    // 220.00    → La3  (une octave en dessous)
frequence(-9);     // 261.63    → Do4

Propriétés calculables immédiates :

  • frequence(12) === 2 * frequence(0) → octave supérieure ;
  • frequence(-12) === frequence(0) / 2 → octave inférieure ;
  • frequence(n + 12) === 2 * frequence(n) → toujours vrai, pour tout n.

Cette unique fonction remplace toute table de fréquences. Les 88 touches d'un piano (blanches et noires) se génèrent en quelques lignes : 

// Génère les 88 touches d'un piano (La0 à Do8)
const touches = Array.from({ length: 88 }, (_, i) => {
    const n = i - 48;             // -48 = La0 ... +39 = Do8
    return { n, frequence: frequence(n) };
});

3.5 — Le timbre

Jouons la même note (même fréquence, même durée, même volume) sur un piano, un violon et une flûte. L'oreille les distingue immédiatement. Pourtant :

  • même fondamentale ;
  • même amplitude ;
  • même durée.

Ce qui change, c'est le timbre. Mais le timbre n'est pas un paramètre mystérieux : c'est la composition en harmoniques du son.

Définition calculable

Un son réel est la somme de sa fondamentale et de ses harmoniques, chacune avec son propre poids : 

// Un son = somme d'harmoniques pondérées
// amplitudes[i] = poids de l'harmonique (i+1)
function echantillon(t, fondamentale, amplitudes) {
    let somme = 0;
    for (let i = 0; i < amplitudes.length; i++) {
        const harmonique = fondamentale * (i + 1);
        somme += amplitudes[i] * Math.sin(2 * Math.PI * harmonique * t);
    }
    return somme;
}

Deux instruments jouant la même note ont la même fondamentale, mais des tableaux d'amplitudes différents. C'est tout. Le timbre, c'est ce tableau. 

// Piano (beaucoup d'harmoniques)
const timbrePiano  = [1.0, 0.5, 0.3, 0.2, 0.15, 0.1];

// Flûte (peu d'harmoniques, son proche du pur)
const timbreFlute  = [1.0, 0.05, 0.02, 0.0, 0.0, 0.0];

// Violon (harmoniques riches et étalées)
const timbreViolon = [1.0, 0.7, 0.6, 0.5, 0.4, 0.35];
⚠️ Ce que ces tableaux sont — et ne sont pas

Les tableaux timbrePiano, timbreFlute, timbreViolon sont des approximations pédagogiques. Ils ne reproduisent pas fidèlement un vrai piano ou un vrai violon. Ils servent uniquement à illustrer le principe : un timbre, c'est un tableau d'amplitudes d'harmoniques.

Pour un vrai instrument, deux méthodes existent :

  • Synthèse : on mesure les amplitudes réelles d'un piano, et on les utilise (voir section 8.3, PeriodicWave).
  • Échantillonnage : on enregistre un piano réel dans un fichier audio, et on le joue (voir section 6, AudioBufferSourceNode).

Le cours utilise des approximations pour expliquer. La production utilise des mesures ou des enregistrements.

Comment passe-t-on du tableau au son ?

Un tableau d'amplitudes ne produit rien tout seul. Il faut le donner à la Web Audio API, qui sait le transformer en onde. L'objet qui fait ça s'appelle PeriodicWave. 

// 1. Le contexte audio (toujours lui)
const audioCtx = new AudioContext();

// 2. Le tableau d'amplitudes de notre "piano pédagogique"
//    Le premier élément DOIT être 0 (décalage DC, pas une harmonique)
const timbrePiano = [0, 1.0, 0.5, 0.3, 0.2, 0.15, 0.1];

// 3. On transforme ce tableau en onde
const real = new Float32Array(timbrePiano);
const imag = new Float32Array(timbrePiano.length);   // zéros
const ondePiano = audioCtx.createPeriodicWave(real, imag);

// 4. On l'utilise dans un oscillateur
const osc = audioCtx.createOscillator();
osc.setPeriodicWave(ondePiano);
osc.frequency.value = 261.63;   // Do4

osc.connect(audioCtx.destination);
osc.start();

Un seul oscillateur, un timbre personnalisé. C'est la méthode native de la Web Audio API. On la détaille en section 8.3.

Ce que le timbre n'est PAS

C'est ici que les confusions sont les plus fréquentes. Le timbre n'est pas :

Ce qu'on pourrait croirePourquoi c'est faux
La hauteur La hauteur dépend de la fondamentale. Deux instruments jouant la même note ont la même hauteur, mais pas le même timbre.
Le volume Le volume dépend de l'amplitude globale. On peut jouer piano et violon au même volume : le timbre diffère quand même.
La durée La durée est indépendante du timbre. Une note courte ou longue garde son timbre.
La forme d'onde « en soi » La forme d'onde est la conséquence des harmoniques. Dire « la forme détermine le timbre » est circulaire : la forme, c'est le timbre rendu visible.

Résumé : le timbre est la répartition d'énergie entre les harmoniques. Point.

Schéma A — Trois timbres, une seule fondamentale

Les trois courbes ont la même période (même fondamentale), mais des formes différentes. C'est ça, le timbre : même note perçue, composition harmonique différente.

Schéma B — Décomposition en harmoniques

En haut, un signal complexe. En dessous, ses quatre premières composantes harmoniques. Le signal complexe est exactement la somme des courbes du dessous.

Les quatre formes d'onde classiques

Les oscillateurs de la Web Audio API proposent quatre formes prédéfinies. Chacune correspond à un profil d'harmoniques précis :

TypeHarmoniques présentesCaractère
sine fondamentale seule son pur
square harmoniques impaires (1, 3, 5, 7…) décroissantes en 1/n creux, électronique
triangle harmoniques impaires décroissantes en 1/n² doux, plus brillant que sine
sawtooth toutes les harmoniques décroissantes en 1/n riche, cuivré

Calculable : le poids de la n-ième harmonique est : 

// Pour square : seules les impaires, poids 1/n
const square = n => n % 2 === 1 ? 1 / n : 0;

// Pour sawtooth : toutes, poids 1/n
const sawtooth = n => 1 / n;

// Pour triangle : impaires, poids 1/n²
const triangle = n => n % 2 === 1 ? 1 / (n * n) : 0;

On peut donc reconstruire chaque forme d'onde à partir de ses harmoniques : 

function onde(type, t, fondamentale, nbHarmoniques = 10) {
    let somme = 0;
    for (let n = 1; n <= nbHarmoniques; n++) {
        let poids = 0;
        if (type === "square")   poids = n % 2 === 1 ? 1 / n : 0;
        if (type === "sawtooth") poids = 1 / n;
        if (type === "triangle") poids = n % 2 === 1 ? 1 / (n * n) : 0;
        somme += poids * Math.sin(2 * Math.PI * fondamentale * n * t);
    }
    return somme;
}

Schéma C — Reconstruction progressive d'une onde carrée

De haut en bas : 1, 3, 5 puis 10 harmoniques sommées. Plus on ajoute d'harmoniques, plus la courbe se rapproche d'un créneau. La forme d'onde n'est rien d'autre que la somme de ses harmoniques.

À retenir :

Le timbre est la répartition d'énergie entre les harmoniques. Il ne dépend ni de la hauteur, ni du volume, ni de la durée. Deux sons de même fondamentale mais de tableaux d'amplitudes différents ont des timbres différents — et c'est calculable. Pour transformer un tableau d'amplitudes en son réel, on utilise PeriodicWave (voir section 8.3).

4. Numérisation du son

4.1 — Pourquoi numériser ?

Un ordinateur ne sait stocker que des nombres. Un signal analogique est une fonction continue : entre deux instants, il y a une infinité de valeurs. On ne peut pas toutes les stocker.

Numériser, c'est faire deux opérations indépendantes :

OpérationCe qu'on faitCe qu'on perd
Échantillonnage On mesure le signal à intervalles réguliers Le signal entre deux mesures
Quantification On arrondit chaque mesure à un niveau disponible La précision de chaque mesure

C'est tout. Le reste (Nyquist, aliasing, distorsion) découle de ces deux opérations.

4.2 — Échantillonnage

On mesure l'amplitude du signal à intervalles réguliers. Le nombre de mesures par seconde est la fréquence d'échantillonnage Fe. 

// Échantillonne un signal à Fe Hz pendant une durée donnée
function echantillonner(signal, Fe, duree) {
    const echantillons = [];
    for (let t = 0; t < duree; t += 1 / Fe) {
        echantillons.push(signal(t));
    }
    return echantillons;
}

// Exemple : une sinusoïde à 440 Hz, échantillonnée à 8000 Hz
const signal = t => Math.sin(2 * Math.PI * 440 * t);
const mesures = echantillonner(signal, 8000, 0.001);  // 8 mesures

Ce qu'on perd : tout ce qui se passe entre deux mesures. Si le signal change plus vite que la période d'échantillonnage, on ne le voit pas.

Schéma D — Échantillonnage d'une sinusoïde

La courbe bleue est le signal continu. Les points jaunes sont les échantillons prélevés à intervalles réguliers. Entre deux points, on ne sait rien du signal.

4.3 — Le problème : aliasing

Que se passe-t-il si le signal oscille plus vite que la fréquence d'échantillonnage ?

Prenons un signal à 700 Hz, échantillonné à 1000 Hz :

const signal = t => Math.sin(2 * Math.PI * 700 * t);
const Fe = 1000;

// Points échantillonnés (tous les 1 ms)
// t = 0.000, 0.001, 0.002, ...
// signal(0.000) = sin(0)          = 0
// signal(0.001) = sin(2π × 0.7)   = -0.951
// signal(0.002) = sin(2π × 1.4)   = 0.588
// signal(0.003) = sin(2π × 2.1)   = -0.951
// ...

Le problème : ces points ne décrivent pas un signal à 700 Hz. Ils décrivent un signal à 300 Hz. C'est l'aliasing : une fréquence élevée se fait passer pour une fréquence plus basse. 

// Vérification : 700 Hz et -300 Hz donnent les mêmes échantillons
// à Fe = 1000 Hz
const freqApparente = 700 - 1000;   // = -300 Hz
// En valeur absolue : 300 Hz

// Preuve : sin(2π × 700 × t) et sin(2π × (-300) × t)
// aux instants t = k / 1000, donnent la même valeur.

Formule de l'aliasing

Une fréquence f échantillonnée à Fe est perçue comme :

function frequenceApparente(f, Fe) {
    // Repliement dans l'intervalle [-Fe/2, Fe/2]
    const fMod = ((f + Fe / 2) % Fe + Fe) % Fe - Fe / 2;
    return Math.abs(fMod);
}

frequenceApparente(700, 1000);   // 300 Hz
frequenceApparente(1500, 1000);  // 500 Hz
frequenceApparente(400, 1000);   // 400 Hz (pas d'aliasing)
frequenceApparente(600, 1000);   // 400 Hz (alias !)

Conséquence : deux fréquences différentes peuvent produire exactement les mêmes échantillons. Impossible de les distinguer après coup.

Schéma E — Aliasing

En bleu, le signal réel à 700 Hz. En jaune, ses échantillons à 1000 Hz. En rouge pointillé, le signal à 300 Hz qui passe par exactement les mêmes points. L'ordinateur ne peut pas savoir lequel était le vrai signal.

4.4 — Le théorème de Nyquist-Shannon

Maintenant qu'on a vu l'aliasing, le théorème devient évident :

Théorème de Nyquist-Shannon :

Pour éviter l'aliasing, il faut que Fe > 2 × f_max.

Pourquoi 2 ? Parce qu'il faut au moins deux points par cycle pour distinguer une oscillation d'une autre. Avec moins de deux points, on ne peut pas savoir si le signal monte ou descend. 

// Conséquence : la fréquence maximale représentable est Fe / 2
const frequenceMax = Fe => Fe / 2;

frequenceMax(8000);    // 4000 Hz  (téléphone)
frequenceMax(44100);   // 22050 Hz (CD)
frequenceMax(48000);   // 24000 Hz (vidéo)

C'est pour ça que le CD utilise 44 100 Hz : on veut représenter jusqu'à 20 000 Hz (limite de l'audition humaine), donc il faut Fe > 40 000. 44 100 est la valeur standard la plus proche.

4.5 — Quantification

Une fois le signal échantillonné, chaque mesure est un nombre réel. On l'arrondit à un niveau disponible. Le nombre de bits n donne 2^n niveaux. 

// Quantifie un échantillon sur n bits (intervalle [-1, 1])
function quantifier(valeur, bits) {
    const niveaux = 2 ** bits;
    const pas = 2 / niveaux;               // taille d'un niveau
    return Math.round(valeur / pas) * pas;
}

quantifier(0.37, 4);   // 0.375   (4 bits → 16 niveaux)
quantifier(0.37, 8);   // 0.3672  (8 bits → 256 niveaux)
quantifier(0.37, 16);  // 0.37000 (16 bits → 65536 niveaux)

Erreur maximale : pas / 2 = 1 / 2^n.

  • 8 bits → erreur max ≈ 0,002 (qualité faible) ;
  • 16 bits → erreur max ≈ 0,000015 (qualité CD) ;
  • 24 bits → erreur max ≈ 0,00000006 (studio).

Schéma F — Quantification

En bleu, le signal continu. En gris, les niveaux disponibles (ici 8 niveaux, soit 3 bits). En jaune, les échantillons quantifiés. Plus il y a de niveaux, plus la courbe jaune colle à la courbe bleue.

4.6 — Calcul de taille

Taille d'un fichier audio non compressé :

// Taille en octets
function tailleAudio(Fe, bits, canaux, duree) {
    return Fe * (bits / 8) * canaux * duree;
}

// 1 minute en qualité CD stéréo
tailleAudio(44100, 16, 2, 60);
// 10 584 000 octets ≈ 10,1 Mo

Pourquoi compresser ? Parce que 10 Mo la minute, c'est 600 Mo l'heure. D'où les codecs (section suivante).

5. Formats et compression

5.1 — Pourquoi compresser ?

On a vu qu'une minute d'audio CD pèse environ 10 Mo. Une chanson de 3 minutes pèse 30 Mo. Un album de 12 titres pèse 360 Mo. Multiplié par des millions d'utilisateurs, c'est ingérable.

Compresser, c'est réduire la taille en supprimant de l'information. Deux stratégies possibles :

StratégiePrincipeRésultat
Sans perte On réorganise l'information pour qu'elle prenne moins de place Le signal reconstruit est identique à l'original
Avec perte On supprime l'information que l'oreille ne perçoit pas Le signal reconstruit est différent, mais perçu comme identique

5.2 — Compression sans perte

L'idée est simple : au lieu de stocker chaque valeur, on stocke des répétitions. C'est le principe du run-length encoding (RLE). 

// Signal original : 9 valeurs
const original = [1, 1, 1, 1, 1, 0, 0, 1, 1];

// Version compressée : 3 paires (valeur, répétitions)
const compresse = [[1, 5], [0, 2], [1, 2]];

// Décompression
function decompresser(compresse) {
    const sortie = [];
    for (const [valeur, repetitions] of compresse) {
        for (let i = 0; i < repetitions; i++) {
            sortie.push(valeur);
        }
    }
    return sortie;
}

decompresser(compresse);
// [1, 1, 1, 1, 1, 0, 0, 1, 1]   → identique à l'original

Résultat : 9 valeurs → 3 paires. Le signal reconstruit est bit pour bit identique à l'original. Aucune perte.

Les formats sans perte (FLAC, ALAC) utilisent des techniques plus sophistiquées (prédiction linéaire, codage entropique), mais le principe reste le même : réorganiser sans supprimer. Gain typique : 30 à 50 %.

Schéma G — Compression sans perte

En haut, le signal original. En bas, le signal reconstruit après compression puis décompression. Les deux courbes sont exactement superposées : aucune information n'a été perdue.

5.3 — Compression avec perte

Ici, on accepte de supprimer de l'information, à condition que l'oreille ne s'en aperçoive pas. Comment ? En exploitant deux propriétés de l'audition :

  • Le masquage fréquentiel : un son fort rend inaudible un son faible proche en fréquence.
  • La sensibilité non uniforme : l'oreille perçoit mal certaines bandes de fréquences (surtout les très aiguës).

Exemple calculable : supprimer des harmoniques

Reprenons notre modèle de timbre. Un son est une somme d'harmoniques pondérées. Si on supprime les harmoniques les plus faibles, on modifie le signal — mais l'oreille ne fera pas la différence. 

// Timbre original : 8 harmoniques
const original = [1.0, 0.7, 0.5, 0.4, 0.2, 0.1, 0.05, 0.02];

// Après compression : on garde les 4 premières
const compresse = [1.0, 0.7, 0.5, 0.4, 0, 0, 0, 0];

// Le signal reconstruit est différent...
// ... mais les harmoniques supprimées (5 à 8) ont un poids
// total de 0.37 sur 2.97, soit ~12% de l'énergie.
// L'oreille ne perçoit pas cette différence dans un contexte réel.

Ce qu'on perd concrètement : les harmoniques faibles, qui contribuent à la « brillance » du son. Sur un instrument solo, ça s'entend. Sur un morceau complet avec plusieurs instruments, non.

Schéma H — Compression avec perte

En haut, le signal original (8 harmoniques). En bas, le signal après suppression des harmoniques 5 à 8. Les deux courbes sont visuellement différentes, mais un auditeur ne distinguerait pas les deux sons dans un contexte réel.

5.4 — Le masquage fréquentiel

C'est le cœur de la compression avec perte. Voici l'idée :

Masquage fréquentiel :

Quand deux sons sont proches en fréquence et que l'un est beaucoup plus fort que l'autre, le son faible devient inaudible. Le codec peut donc le supprimer sans que l'auditeur s'en aperçoive.

Exemple concret : un violon joue un La à 440 Hz très fort. Une flûte joue un La à 445 Hz très faible. L'oreille n'entend qu'un seul La. Le codec supprime la flûte. 

// Deux signaux proches en fréquence
const fort  = t => 1.0 * Math.sin(2 * Math.PI * 440 * t);
const faible = t => 0.05 * Math.sin(2 * Math.PI * 445 * t);

// Signal total
const total = t => fort(t) + faible(t);

// Après masquage : on ne garde que le fort
const apresMasquage = t => fort(t);

// Le faible (amplitude 0.05) est sous le seuil de perception
// quand il est proche du fort (440 vs 445 Hz).

Schéma I — Masquage fréquentiel

En bleu, le son fort (440 Hz). En jaune, le son faible (445 Hz). En rouge pointillé, le seuil de perception. Le son faible est sous le seuil près du son fort : il est masqué, donc supprimable.

5.5 — Les formats audio

Maintenant qu'on comprend les deux stratégies, les formats deviennent lisibles :

FormatTypeUsage
WAV Non compressé Édition, masterisation (référence)
FLAC Sans perte Archivage, audiophiles (gain ~40 %)
ALAC Sans perte Écosystème Apple (gain ~40 %)
MP3 Avec perte Diffusion générale (gain ~90 %)
AAC Avec perte Streaming, mobile (gain ~90 %)
OGG Vorbis Avec perte Jeux vidéo, logiciel libre (gain ~90 %)
Opus Avec perte Web moderne, visioconférence (gain ~95 %)
Comment choisir ?
  • Archivage → sans perte (FLAC).
  • Écoute courante → avec perte (AAC, Opus).
  • Streaming basse latence → Opus.
  • Compatibilité maximale → MP3 (vieux mais universel).
À retenir :

La compression sans perte réorganise l'information sans la supprimer. La compression avec perte supprime l'information inaudible (harmoniques faibles, sons masqués). Les deux réduisent la taille, mais seule la seconde modifie le signal.

6. L'élément audio

6.1 — À quoi sert <audio> ?

<audio> est un élément HTML natif. Il fait une seule chose : lire un fichier audio. Il fournit :

  • un lecteur avec boutons play/pause/volume ;
  • une API JS minimale (play(), pause(), currentTime, volume).

C'est l'équivalent de <img> pour le son. Simple, universel, suffisant pour 90 % des cas :

  • lire un podcast ;
  • jouer une musique de fond ;
  • diffuser un fichier audio dans une page.
<audio id="lecteur" controls>
    <source src="musique.mp3" type="audio/mpeg">
    Votre navigateur ne supporte pas l'audio HTML5.
</audio>
const lecteur = document.getElementById("lecteur");

lecteur.play();
lecteur.pause();
lecteur.currentTime = 10;   // aller à 10 secondes
lecteur.volume = 0.5;       // 50 %
lecteur.loop = true;

Ce qu'on peut faire : lire, mettre en pause, se déplacer, régler le volume. Ce qu'on ne peut pas faire : accéder au signal, le filtrer, le modifier, l'analyser.

6.2 — Pourquoi <audio> ne suffit pas

Voici la question qui tue : peut-on filtrer un son avec <audio> ?

Non. <audio> est une boîte noire. On peut lui dire « joue », « pause », « volume 50 % ». On ne peut pas lui dire « coupe les aiguës au-dessus de 800 Hz », « ajoute un écho », « affiche le spectre en temps réel ».

Pour ça, il faut accéder au signal — c'est-à-dire à la suite de nombres qu'on a étudiée dans les sections précédentes. <audio> ne donne pas accès à ces nombres. 

// Avec

C'est là que la Web Audio API entre en jeu. Elle donne accès au signal, et donc à toutes les opérations qu'on a vues : filtres, gains, enveloppes, analyse.

6.3 — La solution : brancher <audio> dans un graphe Web Audio

Au lieu d'opposer <audio> et la Web Audio API, on les combine. Un élément <audio> peut devenir une source dans un graphe audio, via MediaElementSourceNode. 

// 1. Un contexte audio
const audioCtx = new AudioContext();

// 2. Un élément

Ce qui se passe :

  1. <audio> fournit le signal (le fichier MP3 décodé).
  2. createMediaElementSource capture ce signal et le fait entrer dans le graphe.
  3. On peut le traiter : filtres, gains, analyse, effets.
  4. Le signal traité arrive à audioCtx.destination, c'est-à-dire aux haut-parleurs.
Attention :

Une fois qu'un <audio> est branché dans un graphe Web Audio, son signal ne va plus directement aux haut-parleurs. Il passe obligatoirement par le graphe. Si on oublie de connecter à destination, on n'entend rien.

Schéma J — <audio> seul

Un élément <audio> connecté directement aux haut-parleurs. Aucun traitement possible : le signal est une boîte noire.

Schéma K — <audio> dans le graphe Web Audio

L'élément <audio> est capturé par un MediaElementSource, puis traverse un filtre et un gain avant d'atteindre la destination. Le signal est maintenant accessible et modifiable.

6.4 — <audio> vs AudioBufferSourceNode

La Web Audio API propose aussi une autre façon de lire un fichier : AudioBufferSourceNode. Différence :

Critère <audio> + MediaElementSource AudioBufferSourceNode
Source Fichier streamé Fichier entièrement chargé en mémoire
Chargement Progressif (streaming) Attente complète avant lecture
Latence Plus élevée Très faible
Contrôle play / pause / seek Contrôle total sur le buffer
Usage Musique longue, podcast Sons courts, jeux, instruments 
// AudioBufferSourceNode : chargement complet puis lecture
const audioCtx = new AudioContext();

async function chargerEtJouer(url) {
    const reponse = await fetch(url);
    const tableau = await reponse.arrayBuffer();
    const buffer = await audioCtx.decodeAudioData(tableau);

    const source = audioCtx.createBufferSource();
    source.buffer = buffer;
    source.connect(audioCtx.destination);
    source.start();
}

chargerEtJouer("son-court.mp3");

Règle simple :

  • Fichier long (musique, podcast) → <audio> + MediaElementSource.
  • Son court (effet, note, sample) → AudioBufferSourceNode.

8.1 — Paramètres principaux

Un OscillatorNode produit un signal périodique à une fréquence donnée.

8.2 — Exemple : un La 440 Hz

// 2. L'oscillateur
const osc = audioCtx.createOscillator();

8.3 — Comment obtenir un timbre riche ?

Un oscillateur avec type = "sine" produit une seule harmonique. C'est un son pur. Pour un timbre riche (piano, violon), il faut plusieurs harmoniques. Comment faire ?

Il y a trois méthodes. La plus utile est PeriodicWave, la méthode native de la Web Audio API.

Méthode recommandée — PeriodicWave

PeriodicWave transforme un tableau d'amplitudes en une forme d'onde personnalisée. Un seul oscillateur suffit pour produire un timbre riche. 

// 1. Le contexte
const audioCtx = new AudioContext();

// 2. Le tableau d'amplitudes des harmoniques
//    Premier élément = 0 (décalage DC, pas une harmonique)
//    Ensuite : amplitude de la fondamentale, de la 2e harmonique, etc.
const amplitudes = [0, 1.0, 0.5, 0.3, 0.2, 0.15, 0.1];

// 3. Transformation du tableau en onde
const real = new Float32Array(amplitudes);
const imag = new Float32Array(amplitudes.length);   // zéros

const ondePersonnalisee = audioCtx.createPeriodicWave(real, imag);

// 4. Utilisation dans un oscillateur normal
const osc = audioCtx.createOscillator();
osc.setPeriodicWave(ondePersonnalisee);
osc.frequency.value = 261.63;   // Do4

// 5. Connexion et démarrage
const gain = audioCtx.createGain();
gain.gain.value = 0.3;

osc.connect(gain);
gain.connect(audioCtx.destination);

osc.start();

// 6. Arrêt après 1 seconde (précision à l'échantillon)
const maintenant = audioCtx.currentTime;
osc.stop(maintenant + 1);

Un seul nœud oscillateur, un timbre personnalisé. C'est la méthode à utiliser en production pour tout timbre synthétique.

Les autres méthodes

Pour information, les deux autres approches possibles :

Méthode Principe Avantage Inconvénient
Synthèse additive Un oscillateur par harmonique, additionnés dans un gain Colle au modèle mathématique Lourd (N nœuds par note)
PeriodicWave Un oscillateur avec un tableau d'amplitudes Léger, natif, propre Il faut connaître les amplitudes
Échantillonnage On joue un fichier audio enregistré Timbre réel (vrai piano) Fichier lourd, pas de synthèse
Quelle méthode pour quel usage ?
  • Son pur (test, bip) → OscillatorNode avec type = "sine".
  • Timbre synthétique → PeriodicWave.
  • Instrument réel (piano, violon) → échantillonnage (AudioBufferSourceNode, section 6.4).

9. Façonner le son : enveloppe

Un son brut qui commence et s'arrête brutalement produit un clic désagréable. On façonne son amplitude avec une enveloppe ADSR :

PhaseSignification
AttackTemps pour atteindre le volume maximal
DecayTemps pour redescendre au volume de maintien
SustainVolume maintenu tant que la note est tenue
ReleaseTemps pour revenir à zéro après relâchement

Implémentation avec un GainNode

// audioCtx est supposé déjà créé et démarré
const gain = audioCtx.createGain();
gain.gain.value = 0;

const maintenant = audioCtx.currentTime;

// Attaque
gain.gain.linearRampToValueAtTime(0.5, maintenant + 0.05);

// Decay
gain.gain.linearRampToValueAtTime(0.3, maintenant + 0.2);

// Sustain (maintien)
gain.gain.setValueAtTime(0.3, maintenant + 0.2);

Puis, au relâchement de la touche :

// audioCtx est supposé déjà créé et démarré
const maintenant = audioCtx.currentTime;
gain.gain.cancelScheduledValues(maintenant);
gain.gain.setValueAtTime(gain.gain.value, maintenant);
gain.gain.linearRampToValueAtTime(0, maintenant + 0.3);

13. À retenir — Jour 4

  • Un AudioContext a un cycle de vie : suspended → running → closed. On le démarre avec resume() après une action utilisateur.
  • audioCtx.currentTime est l'horloge du contexte. On programme les événements avec start(t), stop(t), et les rampes.
  • Un OscillatorNode ne peut être démarré qu'une fois.
  • Le son est une onde de pression caractérisée par sa fréquence, son amplitude et son timbre.
  • La fréquence est le nombre de cycles par seconde ; la période en est l'inverse. Doubler la fréquence donne l'octave supérieure.
  • Une octave compte 12 demi-tons (7 notes naturelles + 5 altérées). La formule frequence(n) = 440 * 2 ** (n / 12) remplace toute table.
  • Le timbre est la répartition d'énergie entre les harmoniques. Il ne dépend ni de la hauteur, ni du volume, ni de la durée.
  • Les tableaux de timbre du cours sont des approximations pédagogiques. Pour un son réel : PeriodicWave (synthèse) ou échantillonnage (vrai instrument).
  • Numériser = échantillonner (mesurer à intervalles réguliers) puis quantifier (arrondir à des niveaux).
  • L'aliasing se produit quand Fe < 2 × f_max : une fréquence élevée se fait passer pour une fréquence basse.
  • Le théorème de Nyquist-Shannon impose Fe > 2 × f_max pour éviter l'aliasing.
  • La compression sans perte réorganise l'information (FLAC) ; la compression avec perte supprime l'information inaudible (MP3, AAC, Opus).
  • Le masquage fréquentiel est le principe clé de la compression avec perte : un son fort rend inaudible un son faible proche.
  • <audio> lit un fichier mais ne donne pas accès au signal. Pour le traiter, on le branche dans un graphe Web Audio via MediaElementSource.
  • La Web Audio API modélise le traitement audio comme un graphe de nœuds.
  • Pour un timbre riche : PeriodicWave (synthèse) ou échantillonnage (instrument réel).
  • L'enveloppe ADSR façonne l'amplitude dans le temps.
