Manipulation d'images dans Canvas

Charger, redimensionner, rogner, filtrer : agrandissement, miniaturisation, couleurs et effets

Un canvas n'est pas seulement un espace de dessin vectoriel. C'est aussi un tableau de pixels que nous pouvons lire, modifier et réécrire. Ce cours explore cette dimension : comment transformer une image, pixel par pixel, pour produire des effets visuels.

Progression : Comprendre → Charger → Afficher → Exporter → Redimensionner → Rogner → Pixels → Couleurs → Filtres → Effets → Composer → Exporter le résultat

Durée indicative : 6 à 8 heures | Prérequis : Canvas 2D, JavaScript, boucles, tableaux, fonctions

Objectif général : être capable de construire une petite chaîne complète de traitement d’image : charger une image, la contrôler, la redimensionner, la rogner, modifier ses pixels, lui appliquer des effets, la composer avec d’autres éléments et exporter le résultat sous forme d’image.

1. Introduction : de la forme au pixel

Jusqu'ici, nous dessinions avec des formes vectorielles :

ctx.fillRect(100, 80, 20, 20);
ctx.arc(200, 150, 40, 0, Math.PI * 2);
ctx.lineTo(300, 200);

Avec les images, nous changeons complètement de nature. Une image dans Canvas est une grille de pixels.

Forme vectorielle

Décrite par des coordonnées et des équations. Redimensionnable sans perte.

cercle = (centre, rayon)

Image bitmap

Décrite par une grille de pixels colorés. Chaque pixel a une couleur fixe.

pixel = (R, G, B, A)

Anatomie d'un pixel

Chaque pixel est composé de quatre canaux :

CanalSignificationValeurs
RRouge0 à 255
GVert0 à 255
BBleu0 à 255
AAlpha (transparence)0 (transparent) à 255 (opaque)

Pour une image de 300×200 pixels, cela fait :

300 × 200 × 4 = 240 000 valeurs

Toutes ces valeurs sont stockées dans un tableau plat de type Uint8ClampedArray. C'est cette structure que nous allons lire et modifier.

À retenir : dans ce tableau, les quatre valeurs d'un pixel se suivent. Le pixel 0 occupe les indices 0,1,2,3 ; le pixel 1 occupe les indices 4,5,6,7 ; et ainsi de suite. C'est pourquoi on parcourt souvent ce tableau avec un pas de 4.

1.1 Les trois niveaux de travail avec une image

Niveau 1 — Image source

On travaille avec un objet tel que HTMLImageElement, un fichier choisi par l'utilisateur ou une image générée par un autre canvas.

À ce niveau, on s'intéresse surtout à la taille, à l'origine de l'image et à son chargement.

Niveau 2 — Canvas

On dessine l'image dans un canvas. Le canvas devient une surface de composition : images, texte, formes, transparence et filtres peuvent y être combinés.

Niveau 3 — Pixels

Avec getImageData(), on descend jusqu'aux valeurs R,G,B,A. C'est le niveau nécessaire pour créer des filtres personnalisés.

1.2 Une distinction essentielle : fichier image, objet image et canvas

ÉlémentRôleExemple
FichierDonnée stockée sur le disque ou fournie par l'utilisateurphoto.jpg
Image JavaScriptObjet chargé en mémoire et utilisable par Canvasconst img = new Image()
CanvasSurface de dessin et de compositioncanvas.getContext('2d')
ImageDataReprésentation brute des pixelsctx.getImageData(...)

1.3 La chaîne de traitement que nous allons construire

Fichier→ Chargement→ Canvas→ Transformation→ Export

Cette architecture est importante : le canvas n'est pas forcément le fichier final. Il constitue souvent une étape intermédiaire. On peut charger une photo, la modifier dans le canvas, puis transformer le contenu du canvas en image exportable.

2. Charger et afficher une image

2.1 Le chargement asynchrone

Une image se charge de façon asynchrone. On ne peut pas la dessiner avant qu'elle soit prête. Il faut attendre l'événement onload.

const canvas = document.getElementById('cv');
const ctx = canvas.getContext('2d');

const img = new Image();
img.src = 'photo.jpg';

img.onload = () => {
    ctx.drawImage(img, 0, 0);
};

img.onerror = () => {
    console.error("Impossible de charger l'image");
};
Piège classique : si vous appelez drawImage juste après avoir défini img.src, l'image n'est pas encore chargée. Canvas ne dessine rien, sans erreur. Toujours attendre onload.

2.2 Les trois signatures de drawImage

drawImage possède trois formes, de la plus simple à la plus complète.

FormeSignatureUsage
SimpledrawImage(img, x, y)Afficher à taille originale
Avec tailledrawImage(img, x, y, w, h)Redimensionner
ComplètedrawImage(img, sx, sy, sw, sh, dx, dy, dw, dh)Rogner + redimensionner

La forme complète est la plus puissante : elle permet d'extraire une zone de l'image source (sx, sy, sw, sh) et de la placer ailleurs, à une autre taille (dx, dy, dw, dh).

2.4 Lire correctement les coordonnées

Les coordonnées de la source et de la destination ne jouent pas le même rôle.

Source : sx, sy, sw, sh → Destination : dx, dy, dw, dh

Imaginez deux rectangles :

  • rectangle source : « quelle partie de l'image dois-je prendre ? »
  • rectangle destination : « où et à quelle taille dois-je la dessiner ? »
ctx.drawImage(
    img,
    100, 50, 200, 150,   // source
    20, 30, 400, 300     // destination
);

Le même morceau de 200×150 pixels est ici affiché en 400×300 pixels : il est donc agrandi 2 fois.

2.5 Pourquoi séparer source et destination ?

Cette séparation permet de réaliser plusieurs opérations avec une seule instruction :

OpérationRectangle sourceRectangle destination
CopieMême tailleMême taille
MiniatureImage entièrePlus petite
ZoomPetite zoneGrande zone
RecadrageZone choisieNouvelle position
Déformation volontaireUne zoneRapport largeur/hauteur différent

3. Exporter le contenu du Canvas

Idée fondamentale : dès qu'une image est dessinée dans un canvas, le canvas peut devenir une image à son tour. On peut donc construire une image avec JavaScript puis récupérer son contenu sous forme de donnée exportable.

3.1 Pourquoi exporter ?

L'exportation permet de transformer le résultat obtenu dans Canvas en un fichier ou en une donnée utilisable par une autre partie de l'application.

  • enregistrer une image modifiée par l'utilisateur ;
  • créer une miniature ;
  • générer une signature ou un dessin ;
  • produire une capture d'une composition ;
  • télécharger une image après application d'un filtre ;
  • envoyer ensuite le résultat vers un serveur.

3.2 Première méthode : toDataURL()

La méthode toDataURL() transforme le contenu du canvas en Data URL. Il s'agit d'une chaîne de caractères qui contient les données de l'image encodées.

const dataURL = canvas.toDataURL();
console.log(dataURL);

Par défaut, le navigateur produit généralement une image PNG.

3.3 Choisir le format

const png = canvas.toDataURL('image/png');
const jpeg = canvas.toDataURL('image/jpeg');
const webp = canvas.toDataURL('image/webp');
FormatCaractéristiqueUsage courant
PNGCompression sans perte, transparence possiblelogos, captures, dessins, images avec transparence
JPEGCompression avec perte, généralement plus légerphotographies
WebPFormat moderne, compression efficaceimages web lorsque le contexte le permet

3.4 Qualité JPEG et WebP

Pour les formats qui acceptent un paramètre de qualité, on peut fournir une valeur comprise entre 0 et 1.

const resultat = canvas.toDataURL('image/jpeg', 0.8);

Une valeur proche de 1 privilégie la qualité. Une valeur plus faible produit généralement un fichier plus petit, mais avec davantage de pertes.

Attention : le paramètre de qualité ne signifie pas « agrandir la résolution ». Il agit principalement sur la compression du format choisi.

3.5 Télécharger directement le résultat

Une Data URL peut être utilisée comme destination d'un lien de téléchargement.

function telechargerCanvas(canvas, nom = 'image.png') {
    const lien = document.createElement('a');

    lien.download = nom;
    lien.href = canvas.toDataURL('image/png');

    lien.click();
}

telechargerCanvas(canvas, 'mon-image.png');

3.6 Méthode recommandée pour des images plus importantes : toBlob()

toDataURL() fabrique une longue chaîne de caractères. Pour des images volumineuses, toBlob() est souvent plus adaptée car elle produit un objet Blob.

canvas.toBlob((blob) => {
    if (!blob) return;

    const url = URL.createObjectURL(blob);

    const lien = document.createElement('a');
    lien.href = url;
    lien.download = 'image.jpg';
    lien.click();

    URL.revokeObjectURL(url);
}, 'image/jpeg', 0.85);

3.7 Comprendre le rôle du Blob

Un Blob représente une quantité de données binaires. Dans notre cas, il représente l'image encodée dans le format choisi.

toDataURL()

Retourne une chaîne.

Très simple pour les petits exemples et les démonstrations.

toBlob()

Retourne un objet binaire via un callback.

Plus approprié pour des fichiers et des traitements plus importants.

3.8 Exporter après une transformation

L'exportation se fait après le dessin ou la transformation. Par exemple :

// 1. Dessiner l'image
ctx.drawImage(img, 0, 0);

// 2. Transformer le canvas
const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
// ... modification des pixels ...
ctx.putImageData(imageData, 0, 0);

// 3. Exporter le résultat
canvas.toBlob(blob => {
    // blob contient l'image finale
}, 'image/png');

3.9 Exporter avec une taille précise

Le format du fichier exporté dépend directement de la taille interne du canvas.

canvas.width = 1200;
canvas.height = 800;

ctx.drawImage(img, 0, 0, 1200, 800);

canvas.toBlob(blob => {
    // image finale : 1200 × 800
}, 'image/jpeg', 0.9);
Important : les dimensions CSS affichées à l'écran et les dimensions internes du canvas sont deux notions différentes. Pour obtenir un fichier de 1200×800 pixels, le canvas doit avoir width="1200" et height="800" au niveau de sa résolution interne.

3.10 Transparence et export

Un PNG peut conserver les informations alpha. Un JPEG ne possède pas de canal alpha : une zone transparente doit donc être remplacée par une couleur lors de la composition/exportation.

// Fond blanc avant export JPEG
ctx.save();
ctx.globalCompositeOperation = 'destination-over';
ctx.fillStyle = '#ffffff';
ctx.fillRect(0, 0, canvas.width, canvas.height);
ctx.restore();

canvas.toBlob(blob => {
    // JPEG avec fond blanc
}, 'image/jpeg', 0.9);

3.11 Exporter uniquement une partie de l'image

On peut créer un second canvas temporaire correspondant à la zone que l'on souhaite exporter.

function exporterZone(source, sx, sy, sw, sh) {
    const temp = document.createElement('canvas');
    temp.width = sw;
    temp.height = sh;

    const tctx = temp.getContext('2d');

    tctx.drawImage(
        source,
        sx, sy, sw, sh,
        0, 0, sw, sh
    );

    return temp;
}

const zone = exporterZone(canvas, 100, 50, 300, 200);
zone.toBlob(blob => {
    // export de la zone seulement
}, 'image/png');

3.12 Vérification : l'image exportée doit être l'image finale

Un piège fréquent consiste à exporter un canvas qui n'est pas celui qui contient le résultat final. Dans une application avec plusieurs canvas, il faut toujours identifier clairement :

  1. le canvas source ;
  2. le canvas de travail ;
  3. le canvas de prévisualisation éventuel ;
  4. le canvas destiné à l'export.
Exercice 0 — Premier export

Chargez une image, affichez-la dans un canvas, ajoutez un texte par-dessus, puis créez deux boutons : « Télécharger PNG » et « Télécharger JPEG ». Ajoutez ensuite un troisième bouton qui exporte seulement un carré central de l'image.

4. Agrandir et miniaturiser

3.1 Redimension simple

// Afficher l'image à 50% de sa taille
ctx.drawImage(img, 0, 0, img.width * 0.5, img.height * 0.5);

// Afficher l'image à 200%
ctx.drawImage(img, 0, 0, img.width * 2, img.height * 2);

3.2 Conserver les proportions

Pour éviter la déformation, on calcule un ratio qui respecte les proportions :

function drawFit(ctx, img, x, y, maxW, maxH) {
    const ratio = Math.min(maxW / img.width, maxH / img.height);
    const w = img.width * ratio;
    const h = img.height * ratio;
    ctx.drawImage(img, x, y, w, h);
}

Cette fonction place l'image dans une « boîte » sans la déformer. Si l'image est plus large que haute, elle sera limitée par la largeur ; sinon, par la hauteur.

4.3 Comprendre le ratio d'aspect

Le ratio d'aspect décrit la relation entre largeur et hauteur :

ratio = largeur / hauteur

Une image de 1600×900 possède un ratio de 1600 / 900 ≈ 1,78. Si on la force dans un rectangle 500×500 en donnant directement ces deux dimensions à drawImage, elle sera déformée.

Il faut donc distinguer trois stratégies :

Contain / Fit

L'image entière est visible. Il peut rester des marges.

Cover

La zone est remplie. Une partie de l'image peut être coupée.

Stretch

On impose largeur et hauteur. L'image peut être déformée.

// FIT : image entière dans la boîte
const ratio = Math.min(maxW / img.width, maxH / img.height);

// COVER : remplir toute la boîte
const ratio = Math.max(maxW / img.width, maxH / img.height);

4.4 Canvas interne et taille CSS

Il ne faut pas confondre :

<canvas width="1200" height="800"></canvas>

avec une simple réduction visuelle en CSS :

canvas {
    width: 600px;
    height: 400px;
}

Dans le second cas, le canvas peut toujours contenir 1200×800 pixels internes, même s'il est affiché sur 600×400 CSS pixels.

4.5 Redimensionner une image pour l'export

function redimensionnerPourExport(img, largeur) {
    const ratio = largeur / img.width;
    const hauteur = Math.round(img.height * ratio);

    const c = document.createElement('canvas');
    c.width = largeur;
    c.height = hauteur;

    const ctx = c.getContext('2d');
    ctx.imageSmoothingEnabled = true;
    ctx.imageSmoothingQuality = 'high';
    ctx.drawImage(img, 0, 0, largeur, hauteur);

    return c;
}

Cette technique est particulièrement utile pour générer automatiquement des vignettes, des aperçus ou plusieurs tailles d'une même image.

3.3 Qualité du redimensionnement

Canvas propose deux propriétés pour contrôler la qualité :

ctx.imageSmoothingEnabled = true;   // lissage activé (par défaut)
ctx.imageSmoothingQuality = 'high'; // 'low' | 'medium' | 'high'
Agrandissement : une image agrandie devient floue ou pixelisée. Le lissage adoucit les bords mais ne crée pas de détail. Une image ne contient que l'information qu'elle possède : on ne peut pas inventer des pixels.

3.4 Miniaturisation de qualité : le downscaling progressif

Réduire une image d'un coup (par exemple de 4000px à 200px) donne souvent un résultat médiocre. Une meilleure approche consiste à réduire par étapes, de moitié en moitié.

function downscale(img, facteurCible) {
    let courant = img;
    let w = img.width, h = img.height;
    let facteur = 1;

    while (facteur * 0.5 >= facteurCible) {
        const tmp = document.createElement('canvas');
        tmp.width = Math.max(1, Math.floor(w / 2));
        tmp.height = Math.max(1, Math.floor(h / 2));
        tmp.getContext('2d').drawImage(courant, 0, 0, tmp.width, tmp.height);
        courant = tmp;
        w = tmp.width;
        h = tmp.height;
        facteur *= 0.5;
    }

    return courant;
}

5. Rogner une image

4.1 Rogner avec drawImage

Le rognage consiste à n'afficher qu'une partie de l'image source.

// Extraire la zone (100,50) de taille 200×150,
// et l'afficher en (0,0) à la même taille
ctx.drawImage(img, 100, 50, 200, 150, 0, 0, 200, 150);
ParamètreSignification
sx, syCoin supérieur gauche de la zone à extraire (source)
sw, shLargeur et hauteur de la zone à extraire
dx, dyOù placer le résultat (destination)
dw, dhLargeur et hauteur du résultat affiché

4.2 Rogner et agrandir en même temps

// Rogner une zone 100×100 puis l'afficher en 300×300
ctx.drawImage(img, 50, 50, 100, 100, 0, 0, 300, 300);

C'est cette technique qui permet de faire un « zoom » sur une partie de l'image.

4.3 Rogner en cercle

Pour un avatar rond par exemple, on utilise clip() :

ctx.save();
ctx.beginPath();
ctx.arc(150, 150, 120, 0, Math.PI * 2);
ctx.clip();
ctx.drawImage(img, 0, 0, img.width, img.height, 30, 30, 240, 240);
ctx.restore();

ctx.clip() définit une zone de dessin. Tout ce qui dépasse est ignoré. Le save() et restore() permettent de restaurer le contexte après.

6. Accéder aux pixels : getImageData et putImageData

5.1 Lire les pixels

const imageData = ctx.getImageData(x, y, largeur, hauteur);

On obtient un objet avec trois propriétés :

PropriétéDescription
imageData.widthLargeur de la zone lue
imageData.heightHauteur de la zone lue
imageData.dataUint8ClampedArray de taille width × height × 4

5.2 Parcourir les pixels

const d = imageData.data;

for (let i = 0; i < d.length; i += 4) {
    const r = d[i];
    const g = d[i + 1];
    const b = d[i + 2];
    const a = d[i + 3];

    // modifier r, g, b, a si besoin
    d[i]     = r;
    d[i + 1] = g;
    d[i + 2] = b;
    d[i + 3] = a;
}
L'incrément de 4 est essentiel. Chaque pixel occupe quatre cases consécutives. Si on incrémente de 1, on lit les canaux séparément, ce qui n'a pas de sens.

6.3 Retrouver l'index d'un pixel à partir de (x, y)

Quand on connaît les coordonnées d'un pixel, son index dans le tableau peut être calculé avec :

const index = (y * imageData.width + x) * 4;

Par exemple, pour le pixel situé en x=10 et y=5 :

const i = (5 * imageData.width + 10) * 4;

const r = d[i];
const g = d[i + 1];
const b = d[i + 2];
const a = d[i + 3];

6.4 Pourquoi un tableau plat ?

Conceptuellement, nous imaginons une grille :

[ pixel ][ pixel ][ pixel ]
[ pixel ][ pixel ][ pixel ]
[ pixel ][ pixel ][ pixel ]

Mais en mémoire, les données sont rangées les unes à la suite des autres :

R G B A | R G B A | R G B A | ...

Cette organisation est efficace, mais elle oblige le programmeur à convertir entre coordonnées 2D et index 1D.

6.5 Préserver l'alpha

const a = d[i + 3];

// modifier R, G, B
// ...

d[i + 3] = a;

Si votre filtre ne doit pas toucher à la transparence, laissez simplement le canal alpha inchangé.

5.3 Écrire les pixels modifiés

ctx.putImageData(imageData, x, y);

Cette méthode écrase la zone avec les nouvelles valeurs. Elle ne se combine pas avec ce qui était déjà dessiné : elle remplace.

5.4 Attention à la sécurité (CORS)

Si l'image vient d'un autre domaine, getImageData est bloqué pour des raisons de sécurité. Le navigateur considère le canvas comme « contaminé ».

Sécurité : pour lire les pixels d'une image externe, il faut soit la servir depuis le même domaine, soit l'charger avec img.crossOrigin = 'anonymous', et que le serveur envoie l'en-tête Access-Control-Allow-Origin.
img.crossOrigin = 'anonymous';
img.src = 'https://autre-domaine.com/photo.jpg';

7. Manipulations de couleurs

Nous allons maintenant appliquer des transformations classiques sur chaque pixel. Toutes ces fonctions prennent un imageData et le modifient en place.

6.1 Renforcer un canal (par exemple le rouge)

function renforcerCanal(imageData, canal, facteur) {
    const d = imageData.data;
    const offset = { r: 0, g: 1, b: 2 }[canal];

    for (let i = offset; i < d.length; i += 4) {
        d[i] = Math.min(255, d[i] * facteur);
    }
}

renforcerCanal(imageData, 'r', 1.5); // rouge renforcé

6.2 Désaturer (niveaux de gris)

La formule la plus courante utilise la luminance perçue :

for (let i = 0; i < d.length; i += 4) {
    const gris = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2];
    d[i]     = gris;
    d[i + 1] = gris;
    d[i + 2] = gris;
}

Ces coefficients reflètent la sensibilité de l'œil : nous percevons mieux le vert que le bleu. Une simple moyenne donnerait un résultat moins naturel.

6.3 Désaturation partielle

Pour doser l'effet entre 0 (inchangé) et 1 (gris total) :

function desaturer(imageData, taux) {
    const d = imageData.data;

    for (let i = 0; i < d.length; i += 4) {
        const gris = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2];
        d[i]     = d[i]     + (gris - d[i])     * taux;
        d[i + 1] = d[i + 1] + (gris - d[i + 1]) * taux;
        d[i + 2] = d[i + 2] + (gris - d[i + 2]) * taux;
    }
}

6.4 Inverser les couleurs (négatif)

for (let i = 0; i < d.length; i += 4) {
    d[i]     = 255 - d[i];
    d[i + 1] = 255 - d[i + 1];
    d[i + 2] = 255 - d[i + 2];
}

L'alpha n'est pas modifié : la transparence est préservée.

6.5 Monochrome (teinte unique)

Transformer l'image en une seule teinte, par exemple bleu :

for (let i = 0; i < d.length; i += 4) {
    const gris = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2];
    d[i]     = gris * 0.2; // peu de rouge
    d[i + 1] = gris * 0.4; // un peu de vert
    d[i + 2] = gris;       // bleu dominant
}

Version plus souple avec une couleur cible :

function monochrome(imageData, couleur) {
    const d = imageData.data;
    const { r, g, b } = couleur;

    for (let i = 0; i < d.length; i += 4) {
        const gris = (0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2]) / 255;
        d[i]     = r * gris;
        d[i + 1] = g * gris;
        d[i + 2] = b * gris;
    }
}

monochrome(imageData, { r: 200, g: 100, b: 50 }); // teinte sépia

6.6 Luminosité et contraste

function luminosite(imageData, delta) {
    const d = imageData.data;
    for (let i = 0; i < d.length; i += 4) {
        d[i]     = Math.min(255, Math.max(0, d[i]     + delta));
        d[i + 1] = Math.min(255, Math.max(0, d[i + 1] + delta));
        d[i + 2] = Math.min(255, Math.max(0, d[i + 2] + delta));
    }
}

function contraste(imageData, facteur) {
    // facteur > 1 → plus de contraste, < 1 → moins
    const d = imageData.data;
    for (let i = 0; i < d.length; i += 4) {
        d[i]     = Math.min(255, Math.max(0, (d[i]     - 128) * facteur + 128));
        d[i + 1] = Math.min(255, Math.max(0, (d[i + 1] - 128) * facteur + 128));
        d[i + 2] = Math.min(255, Math.max(0, (d[i + 2] - 128) * facteur + 128));
    }
}

6.7 Sépia

for (let i = 0; i < d.length; i += 4) {
    const r = d[i], g = d[i + 1], b = d[i + 2];
    d[i]     = Math.min(255, 0.393 * r + 0.769 * g + 0.189 * b);
    d[i + 1] = Math.min(255, 0.349 * r + 0.686 * g + 0.168 * b);
    d[i + 2] = Math.min(255, 0.272 * r + 0.534 * g + 0.131 * b);
}

6.8 Seuil (noir et blanc pur)

const seuil = 128;
for (let i = 0; i < d.length; i += 4) {
    const gris = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2];
    const v = gris > seuil ? 255 : 0;
    d[i] = d[i + 1] = d[i + 2] = v;
}

6.9 Tableau récapitulatif

8. Avant les filtres : construire un pipeline propre

À mesure que les traitements deviennent nombreux, il est important de ne pas modifier définitivement l'image originale à chaque clic.

8.1 Garder une source intacte

const imageOriginale = img;

// Pour chaque nouveau filtre :
ctx.clearRect(0, 0, canvas.width, canvas.height);
ctx.drawImage(imageOriginale, 0, 0);

// puis appliquer le traitement

Cette méthode permet de revenir instantanément à l'original et d'éviter l'accumulation d'erreurs de compression ou de transformations.

8.2 Deux architectures possibles

8.3 Fonction générale de traitement

function traiterImage(img, traitement) {
    const canvas = document.createElement('canvas');
    canvas.width = img.width;
    canvas.height = img.height;

    const ctx = canvas.getContext('2d');
    ctx.drawImage(img, 0, 0);

    const imageData = ctx.getImageData(
        0, 0,
        canvas.width,
        canvas.height
    );

    traitement(imageData);

    ctx.putImageData(imageData, 0, 0);

    return canvas;
}

8.4 Et ensuite ?

Une fois le canvas retourné, la même fonction peut servir à :

  • l'afficher dans la page ;
  • l'afficher dans un autre canvas ;
  • le redimensionner ;
  • l'exporter avec toBlob() ou toDataURL().
Idée clé : séparer « charger », « transformer », « afficher » et « exporter » rend le programme beaucoup plus facile à comprendre et à maintenir.

8. Filtres natifs de Canvas

Canvas propose une propriété ctx.filter qui applique un filtre au prochain dessin. C'est beaucoup plus rapide que de manipuler les pixels, mais on n'a pas accès aux valeurs individuelles.

ctx.filter = 'grayscale(100%)';
ctx.drawImage(img, 0, 0);

ctx.filter = 'blur(5px)';
ctx.drawImage(img, 0, 0);

ctx.filter = 'sepia(80%) brightness(1.2) contrast(1.1)';

9. Effets avancés

8.1 Flou par convolution (moyenne)

Un flou simple consiste à remplacer chaque pixel par la moyenne de ses voisins. On parcourt donc chaque pixel et on calcule la moyenne d'un voisinage (par exemple 3×3).

function flouMoyenne(imageData, taille) {
    const { width, height, data } = imageData;
    const copie = new Uint8ClampedArray(data);
    const r = Math.floor(taille / 2);

    for (let y = 0; y < height; y++) {
        for (let x = 0; x < width; x++) {
            let sr = 0, sg = 0, sb = 0, n = 0;

            for (let dy = -r; dy <= r; dy++) {
                for (let dx = -r; dx <= r; dx++) {
                    const nx = x + dx, ny = y + dy;
                    if (nx < 0 || ny < 0 || nx >= width || ny >= height) continue;
                    const i = (ny * width + nx) * 4;
                    sr += copie[i];
                    sg += copie[i + 1];
                    sb += copie[i + 2];
                    n++;
                }
            }

            const i = (y * width + x) * 4;
            data[i]     = sr / n;
            data[i + 1] = sg / n;
            data[i + 2] = sb / n;
        }
    }
}
Attention : il faut travailler sur une copie des données, sinon les pixels déjà modifiés influencent les suivants. C'est une source classique de bug.

8.2 Détection de contours (Sobel simplifié)

Un contour apparaît là où la luminosité change brutalement. On compare chaque pixel à ses voisins.

function contours(imageData, seuil) {
    const { width, height, data } = imageData;
    const copie = new Uint8ClampedArray(data);

    for (let y = 1; y < height - 1; y++) {
        for (let x = 1; x < width - 1; x++) {
            const i = (y * width + x) * 4;
            const gx =
                -1 * copie[((y-1)*width + (x-1))*4] +
                 1 * copie[((y-1)*width + (x+1))*4] +
                -2 * copie[( y   *width + (x-1))*4] +
                 2 * copie[( y   *width + (x+1))*4] +
                -1 * copie[((y+1)*width + (x-1))*4] +
                 1 * copie[((y+1)*width + (x+1))*4];

            const gy =
                -1 * copie[((y-1)*width + (x-1))*4] +
                -2 * copie[((y-1)*width +  x   )*4] +
                -1 * copie[((y-1)*width + (x+1))*4] +
                 1 * copie[((y+1)*width + (x-1))*4] +
                 2 * copie[((y+1)*width +  x   )*4] +
                 1 * copie[((y+1)*width + (x+1))*4];

            const magnitude = Math.sqrt(gx * gx + gy * gy);
            const v = magnitude > seuil ? 255 : 0;
            data[i] = data[i + 1] = data[i + 2] = v;
        }
    }
}

8.3 Pixelisation (mosaïque)

On regroupe les pixels par blocs et on leur donne une couleur unique.

function pixeliser(imageData, tailleBloc) {
    const { width, height, data } = imageData;

    for (let by = 0; by < height; by += tailleBloc) {
        for (let bx = 0; bx < width; bx += tailleBloc) {
            let sr = 0, sg = 0, sb = 0, n = 0;

            for (let y = by; y < Math.min(by + tailleBloc, height); y++) {
                for (let x = bx; x < Math.min(bx + tailleBloc, width); x++) {
                    const i = (y * width + x) * 4;
                    sr += data[i];
                    sg += data[i + 1];
                    sb += data[i + 2];
                    n++;
                }
            }

            const r = sr / n, g = sg / n, b = sb / n;

            for (let y = by; y < Math.min(by + tailleBloc, height); y++) {
                for (let x = bx; x < Math.min(bx + tailleBloc, width); x++) {
                    const i = (y * width + x) * 4;
                    data[i]     = r;
                    data[i + 1] = g;
                    data[i + 2] = b;
                }
            }
        }
    }
}

8.4 Teinte (hue-rotate) manuelle

Faire tourner la teinte nécessite de convertir en HSL, ce qui est plus complexe. Une approximation existe en RGB, mais elle donne des résultats approximatifs. Pour un vrai hue-rotate, on utilise ctx.filter = 'hue-rotate(90deg)'.

  1. Identifier la source : image, fichier local ou autre canvas.
  2. Déterminer la sortie : dimensions attendues et format d'export.

  5. Tester sur une petite image : les opérations pixel par pixel peuvent être coûteuses.

La règle mentale à retenir :

Une image est un tableau de pixels. Chaque pixel est un groupe de 4 valeurs (R, G, B, A). Modifier une image, c'est parcourir ce tableau et transformer ces valeurs.

Les 10 idées essentielles

  1. Une image dans Canvas est une grille de pixels, chaque pixel ayant 4 canaux (R, G, B, A).
  2. Le chargement d'une image est asynchrone : il faut attendre onload.
  3. drawImage possède trois signatures, dont une complète qui permet de rogner et redimensionner.
  4. Conserver les proportions évite la déformation.
  5. La miniaturisation progressive donne de meilleurs résultats qu'une réduction directe.
  6. getImageData et putImageData permettent de lire et d'écrire les pixels.
  7. On parcourt les pixels avec un pas de 4.
  8. Les filtres classiques (gris, sépia, négatif, seuil) sont des transformations simples appliquées à chaque pixel.
  9. Les filtres natifs (ctx.filter) sont rapides mais ne permettent pas de logique personnalisée.
  10. Les effets avancés (flou, contours, pixelisation) nécessitent de considérer le voisinage des pixels.
  11. toDataURL() permet d'obtenir une représentation exportable sous forme de chaîne.
  12. toBlob() permet de produire un fichier binaire exportable plus adapté aux gros résultats.
  13. Le format PNG conserve la transparence, tandis que JPEG ne possède pas de canal alpha.
  14. La taille interne du canvas détermine la résolution de l'image exportée.
  15. Une application interactive doit idéalement conserver l'image originale et recalculer le résultat.
Pièges à éviter :
  • Dessiner avant onload : rien ne s'affiche.
  • Oublier de copier les données avant une convolution : les pixels modifiés influencent les suivants.
  • Lire les pixels d'une image d'un autre domaine sans CORS : erreur de sécurité.
  • Modifier les pixels sans réinitialiser l'alpha : la transparence peut être altérée.
