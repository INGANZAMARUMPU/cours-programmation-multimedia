2. Introduction à la programmation multimédia

Une application multimédia combine plusieurs types de contenus et plusieurs formes d'interaction. Dans ce module, la partie graphique constitue un langage visuel : les coordonnées, les formes, les couleurs et les transformations sont les briques qui permettent de construire une scène.

Graphique

Images, formes, couleurs, texte, dessins et animations.

Audio

Musique, voix et effets sonores.

Vidéo

Images animées et séquences vidéo.

Interaction

Clavier, souris, tactile, caméra et autres entrées.

Dans cette séance :

On se concentre volontairement sur le dessin 2D statique. Le mouvement et l'interaction appartiennent aux étapes suivantes. Cette restriction est pédagogique : avant de faire bouger un objet, il faut savoir précisément comment le dessiner et comment contrôler son repère.

2.1 Pourquoi commencer par le dessin statique ?

Une animation est essentiellement une répétition de dessins à des instants différents. Si vous ne maîtrisez pas le dessin d'une image, vous aurez beaucoup plus de mal à comprendre pourquoi un objet animé se déplace, tourne ou change d'échelle.

Le raisonnement à retenir est donc : géométrie → dessin → transformation → répétition dans le temps → animation.

3. Modèle mental : comment penser Canvas

Avant d'apprendre les méthodes, il faut construire un modèle mental correct. Imaginez Canvas comme une feuille quadrillée invisible sur laquelle JavaScript donne des instructions de dessin.

3.1 Une surface + un contexte

Le navigateur affiche une surface rectangulaire. JavaScript ne dessine pas directement avec l'élément HTML : il récupère un contexte de rendu. Pour cette séance, il s'agit du contexte "2d". 

const canvas = document.getElementById("scene");
const ctx = canvas.getContext("2d");

Il est utile de distinguer les deux :

ÉlémentRôleQuestion à se poser
canvasSurface HTML sur laquelle le rendu apparaît.Où dessine-t-on ?
ctxContexte contenant les méthodes et l'état de dessin.Comment dessine-t-on ?

3.2 Canvas ne connaît pas votre « maison »

Pour Canvas, une maison n'est pas une primitive magique. Une maison est une composition de primitives : rectangle pour le mur, polygone pour le toit, rectangles pour les fenêtres, etc.

Idée fondamentale :

Le navigateur exécute des commandes de dessin. Il ne comprend pas spontanément « ceci est une maison » ou « ceci est un arbre ». C'est votre programme qui décompose l'objet visuel en éléments géométriques.

3.3 Le dessin est sensible à l'ordre

Si vous dessinez d'abord le soleil puis un grand rectangle couvrant tout le ciel, le rectangle peut recouvrir le soleil. Inversement, dessiner le soleil après le ciel le place visuellement au-dessus.

On peut donc penser la scène comme des couches successives : arrière-plan → éléments éloignés → sol → bâtiments → végétation → détails → texte.

4. HTML5 Canvas

4.1 Déclarer la surface

<canvas id="scene" width="800" height="500"></canvas>

Les attributs width et height définissent la taille interne de la surface de dessin. Dans cet exemple, la surface possède 800 unités horizontales et 500 unités verticales dans son repère de dessin.

Subtilité importante : taille interne ≠ taille CSS.

Modifier uniquement width/height de l'élément ou modifier sa taille avec CSS ne signifie pas la même chose. Le Canvas possède une résolution interne de dessin et peut ensuite être affiché à une autre taille. Pour les exercices de cette séance, on garde les deux notions distinctes.

4.2 Récupérer le contexte 2D

const canvas = document.getElementById("scene");
const ctx = canvas.getContext("2d");

if (!ctx) {
  throw new Error("Le contexte 2D n'est pas disponible.");
}

getElementById() récupère l'élément HTML. Ensuite, getContext("2d") demande au navigateur un contexte de dessin 2D. Toutes les opérations étudiées dans cette séance passent principalement par ctx.

4.3 Le piège classique : exécuter le JavaScript trop tôt

Si le script s'exécute avant que le navigateur ait créé l'élément Canvas dans le DOM, document.getElementById("scene") peut renvoyer null. Une solution simple est de placer le script après le Canvas ou de charger le script avec une stratégie adaptée. 

<canvas id="scene" width="800" height="500"></canvas>
<script src="script.js"></script>
Erreur typique : 
const ctx = document.getElementById("scene").getContext("2d");
// Si #scene n'existe pas encore, une erreur apparaît.

5. Système de coordonnées 2D

5.1 Origine et axes

Le repère Canvas commence par défaut dans le coin supérieur gauche.

ÉlémentDirectionConséquence
Xvers la droiteAugmenter X déplace un objet vers la droite.
Yvers le basAugmenter Y déplace un objet vers le bas.
(0,0)coin supérieur gauchePoint de départ du repère par défaut.
Attention au réflexe mathématique.

Dans un repère cartésien scolaire classique, l'axe Y positif monte. Dans le repère Canvas par défaut, Y positif descend. Il faut donc abandonner l'idée « Y positif = vers le haut » lorsque vous raisonnez directement dans Canvas.

5.2 Comparaison visuelle : repère mathématique vs repère Canvas

Repère mathématique

Y augmente vers le haut.

Repère Canvas

(0,0) est en haut à gauche et Y augmente vers le bas.

5.3 Lire une primitive rectangulaire

ctx.fillRect(100, 50, 120, 80);

Les quatre paramètres correspondent à :

  1. 100 : position X du point de départ ;
  2. 50 : position Y du point de départ ;
  3. 120 : largeur ;
  4. 80 : hauteur.

Pour éviter les confusions, entraînez-vous à lire systématiquement une signature sous la forme position → dimensions : (x, y, largeur, hauteur).

5.4 Coordonnée d'un centre

Beaucoup d'objets sont plus faciles à construire si l'on raisonne à partir de leur centre. Pour un rectangle de largeur w et de hauteur h, dont le coin supérieur gauche est (x, y), son centre est : 

centreX = x + w / 2;
centreY = y + h / 2;

Cette relation deviendra particulièrement importante pour les rotations.

5.5 Dépassement de la surface

Une forme peut être partiellement ou totalement située hors du Canvas. Il ne faut pas supposer que toutes les coordonnées doivent être positives et à l'intérieur des dimensions visibles. Le navigateur ne dessinera simplement que ce qui est visible dans la zone de rendu.

6. Dessiner les formes géométriques

6.1 Rectangle plein : fillRect()

ctx.fillStyle = "royalblue";
ctx.fillRect(100, 80, 150, 100);

fillRect() dessine immédiatement un rectangle rempli avec le fillStyle courant.

Lecture : « utilise le style de remplissage actuel et remplis le rectangle dont le coin de référence est (100,80), de largeur 150 et de hauteur 100 ».

6.2 Rectangle contour : strokeRect()

ctx.strokeStyle = "red";
ctx.lineWidth = 4;
ctx.strokeRect(300, 80, 150, 100);

Ici, on ne remplit pas l'intérieur : on trace le contour avec le style de trait courant.

6.3 Comparaison visuelle : fillRect() vs strokeRect()

Remplir : fillRect

ctx.fillStyle = "#b9c9dc"; ctx.fillRect(70, 45, 150, 90);

La surface intérieure est peinte.

Tracer : strokeRect

ctx.strokeStyle = "#2c5282"; ctx.lineWidth = 6; ctx.strokeRect(70, 45, 150, 90);

Le contour est tracé ; lineWidth devient visible.

MéthodeEffetStyle principal
fillRect()Remplissage immédiatfillStyle
strokeRect()Contour immédiatstrokeStyle, lineWidth
clearRect()Effacement d'une zoneAucun style de couleur

6.4 Effacer n'est pas peindre en transparent

ctx.clearRect(0, 0, canvas.width, canvas.height);

clearRect() sert à nettoyer une zone du Canvas. Conceptuellement, ce n'est pas la même opération que dessiner un rectangle avec une couleur « transparente ». Cette distinction devient importante lorsqu'on travaille avec des arrière-plans, de la transparence et des animations.

6.5 Cercle et arc : arc()

ctx.beginPath();
ctx.arc(200, 300, 50, 0, Math.PI * 2);
ctx.fillStyle = "orange";
ctx.fill();

Les paramètres sont :

  1. 200 : centre X ;
  2. 300 : centre Y ;
  3. 50 : rayon ;
  4. 0 : angle de départ ;
  5. Math.PI * 2 : angle d'arrivée, soit un tour complet.
Radians :

Canvas attend des angles en radians. Les correspondances utiles sont : 0 = 0°, Math.PI / 2 = 90°, Math.PI = 180°, Math.PI * 2 = 360°.

6.6 Pourquoi beginPath() avant un cercle ?

arc() construit un chemin. beginPath() permet de repartir sur un nouveau chemin afin que les sous-chemins précédents ne soient pas involontairement réutilisés lors d'un futur fill() ou stroke().

6.7 Segment

ctx.beginPath();
ctx.moveTo(400, 250);
ctx.lineTo(650, 350);
ctx.strokeStyle = "black";
ctx.lineWidth = 5;
ctx.stroke();

Ici, moveTo() place le point courant sans dessiner de segment. lineTo() crée un segment entre le point courant et le nouveau point. Enfin, stroke() rend le contour du chemin visible.

6.8 Comparaison visuelle : moveTo() vs lineTo()

moveTo : déplacer sans tracer

ctx.moveTo(70,130); ctx.moveTo(210,55); ctx.lineTo(350,130);

Le premier déplacement est invisible.

lineTo : créer un segment

ctx.moveTo(70,130); ctx.lineTo(210,55); ctx.lineTo(350,130);

Chaque lineTo ajoute un segment au chemin.

Distinction essentielle :

moveTo() ne trace pas. lineTo() construit le chemin. stroke() rend ce chemin visible sous forme de contour.

7. Chemins et polygones

Les chemins sont indispensables dès qu'une scène dépasse les rectangles et cercles. Un chemin est une suite de sous-chemins géométriques construits progressivement.

7.1 Anatomie d'un chemin

ctx.beginPath();
ctx.moveTo(100, 100);
ctx.lineTo(200, 100);
ctx.lineTo(150, 200);
ctx.closePath();

ctx.fillStyle = "green";
ctx.fill();

ctx.strokeStyle = "black";
ctx.lineWidth = 2;
ctx.stroke();

Décomposons chaque instruction :

  1. beginPath() : démarre un nouveau chemin ;
  2. moveTo() : place le point de départ ;
  3. les deux lineTo() : ajoutent les côtés ;
  4. closePath() : referme le chemin vers son point de départ ;
  5. fill() : remplit la région définie par le chemin ;
  6. stroke() : trace son contour.

7.2 Comparaison visuelle : fill() vs stroke()

fill()

Le chemin devient une surface remplie.

stroke()

Le même chemin peut servir uniquement à dessiner le contour.

7.3 Comparaison visuelle : pourquoi beginPath() ?

Sans nouveau chemin

Le chemin courant conserve ses anciens segments : un nouveau stroke() peut les redessiner.

Avec beginPath()

beginPath() démarre une nouvelle collection de sous-chemins.

7.4 closePath() n'est pas obligatoire pour tous les dessins

Un chemin ouvert peut être parfaitement adapté à une ligne ou à une série de segments. En revanche, pour un polygone destiné à être fermé visuellement, closePath() évite d'avoir à ajouter manuellement le dernier segment vers le point initial.

7.5 Un même chemin peut être rempli puis contouré

ctx.fillStyle = "green";
ctx.fill();

ctx.strokeStyle = "black";
ctx.stroke();

Le remplissage et le contour sont deux opérations distinctes. On peut donc créer une forme, la remplir avec une couleur, puis tracer son contour avec un autre style.

7.6 Construire une maison avec des chemins

// Toit
ctx.beginPath();
ctx.moveTo(250, 180);
ctx.lineTo(400, 70);
ctx.lineTo(550, 180);
ctx.closePath();

ctx.fillStyle = "#8b4513";
ctx.fill();
ctx.strokeStyle = "#222";
ctx.stroke();

La maison est un bon exemple de composition : le toit est un triangle, mais l'objet « maison » est obtenu par l'association de plusieurs formes.

8. Couleurs, transparence et styles

8.1 Plusieurs écritures d'une couleur

ctx.fillStyle = "red";
ctx.fillStyle = "#ff0000";
ctx.fillStyle = "rgb(255, 0, 0)";
ctx.fillStyle = "rgba(255, 0, 0, 0.5)";

Ces écritures représentent différentes façons de décrire une couleur. Pour rgba(), le quatrième paramètre représente l'alpha, donc le niveau de transparence/opacité selon la convention utilisée par le modèle de couleur.

Subtilité de l'état :

fillStyle reste actif pour les futurs remplissages jusqu'à ce que vous lui affectiez une autre valeur ou que vous restauriez un état précédent avec restore(). Il n'est donc pas nécessaire de le redéfinir avant chaque forme si la même couleur doit être conservée.

8.2 Remplissage et contour ont des styles différents

ctx.fillStyle = "orange";
ctx.strokeStyle = "black";
ctx.lineWidth = 3;

Une forme peut donc avoir simultanément un intérieur orange et un contour noir.

8.3 Dégradé linéaire

const gradient = ctx.createLinearGradient(0, 0, 0, 400);

gradient.addColorStop(0, "#87ceeb");
gradient.addColorStop(1, "#1e3a8a");

ctx.fillStyle = gradient;
ctx.fillRect(0, 0, 800, 400);

Un dégradé linéaire est défini par une ligne de départ et d'arrivée. Les colorStop indiquent quelle couleur apparaît à quelle position relative sur cette ligne.

8.4 Dégradé radial

const radial = ctx.createRadialGradient(
  400, 200, 10,
  400, 200, 200
);

radial.addColorStop(0, "yellow");
radial.addColorStop(1, "orange");

ctx.fillStyle = radial;
ctx.fillRect(0, 0, 800, 400);

Le dégradé radial repose sur deux cercles : un cercle de départ et un cercle d'arrivée. Cette notion est particulièrement utile pour des effets de lumière, de soleil ou de volume.

8.5 Comparaison visuelle : dégradé linéaire vs radial

createLinearGradient()

La transition suit une direction entre deux points.

createRadialGradient()

La transition rayonne autour d'un centre.

8.6 Style du contour

ctx.strokeStyle = "navy";
ctx.lineWidth = 3;
ctx.lineCap = "round";
ctx.lineJoin = "round";
PropriétéQuestionEffet
strokeStyleDe quelle couleur est le contour ?Couleur / style du trait.
lineWidthQuelle épaisseur ?Largeur du trait.
lineCapComment se termine un segment ?Extrémité du trait.
lineJoinComment deux segments se rejoignent-ils ?Jonction des segments.

8.7 Erreur classique : croire qu'un style « appartient » à la forme

Canvas n'attache pas automatiquement une propriété comme un objet graphique possédant son propre style permanent. Le contexte possède un état courant. Il faut donc penser : « je configure l'état, puis je dessine ».

9. Texte : écrire dans le repère graphique

ctx.font = "30px Arial";
ctx.fillStyle = "black";
ctx.textAlign = "center";
ctx.textBaseline = "middle";

ctx.fillText("Bonjour Canvas", 400, 200);

9.1 Les quatre éléments à distinguer

Propriété / méthodeRôle
fontDéfinit la police et la taille.
textAlignDéfinit l'alignement horizontal par rapport à X.
textBaselineDéfinit la référence verticale du texte.
fillText()Dessine le texte rempli.
strokeText()Dessine le contour du texte.

9.2 Pourquoi l'alignement est important

Lorsque vous écrivez fillText("Titre", 400, 100), le point (400,100) n'est pas automatiquement le coin supérieur gauche du texte. Sa signification dépend de textAlign et textBaseline.

Pour centrer un titre autour d'un point : 

ctx.textAlign = "center";
ctx.textBaseline = "middle";
ctx.fillText("Titre", 400, 100);

9.3 Texte avec contour

ctx.font = "48px Georgia";
ctx.strokeStyle = "navy";
ctx.lineWidth = 2;
ctx.strokeText("Titre", 400, 100);
À retenir :

Le texte utilise lui aussi le repère graphique. Si le repère est transformé avec translate(), rotate() ou scale(), le texte dessiné ensuite est concerné par ces transformations.

10. L'état graphique du contexte

C'est l'une des notions les plus importantes et les plus souvent mal comprises. Le contexte 2D possède un ensemble de propriétés courantes : couleur de remplissage, couleur de contour, largeur de ligne, police, alignement, transformations, etc.

10.1 Penser en « état courant »

ctx.fillStyle = "red";
ctx.fillRect(10, 10, 50, 50);

ctx.fillRect(80, 10, 50, 50);

Les deux rectangles sont rouges parce que le deuxième dessin utilise encore le fillStyle courant.

10.2 save() et restore()

ctx.save();

ctx.fillStyle = "orange";
ctx.lineWidth = 10;
ctx.translate(300, 200);

ctx.fillRect(-25, -25, 50, 50);

ctx.restore();

// Le contexte revient à l'état sauvegardé.

save() empile l'état courant. restore() récupère l'état sauvegardé correspondant. Le mécanisme fonctionne comme une pile : plusieurs sauvegardes peuvent être imbriquées.

10.3 Comparaison visuelle : avec et sans isolation

Sans isolation

Le second objet hérite du lineWidth modifié.

Avec isolation

Après restore(), l'état revient à celui sauvegardé.

Erreur fréquente :

Modifier le repère ou les styles sans les restaurer peut produire des effets surprenants plusieurs dizaines de lignes plus tard. Lorsqu'une fonction dessine un objet avec son propre repère ou ses propres styles, save() / restore() rendent cette fonction beaucoup plus sûre.

11. Transformations graphiques

Une transformation ne « déplace » pas physiquement les pixels déjà dessinés. Elle modifie la manière dont les prochaines coordonnées sont interprétées. C'est donc surtout le repère de dessin qui est transformé.

11.1 Translation : translate(x, y)

ctx.save();

ctx.translate(300, 200);
ctx.fillRect(0, 0, 100, 60);

ctx.restore();

Après la translation, le point (0,0) du repère transformé correspond au point situé vers (300,200) dans le repère précédent. Ainsi, dessiner à (0,0) après la translation ne dessine plus dans le coin supérieur gauche de la surface.

11.2 Comparaison visuelle : sans et avec translate()

Sans translate()

Le rectangle utilise directement le repère initial.

Avec translate(170,55)

ctx.translate(170,55); ctx.fillRect(0,0,120,70);

Les mêmes coordonnées locales commencent à la nouvelle origine.

11.3 Rotation : rotate(angle)

ctx.save();

ctx.translate(400, 250);
ctx.rotate(Math.PI / 4);

ctx.fillRect(-50, -30, 100, 60);

ctx.restore();

rotate() attend des radians. Surtout, la rotation se fait autour de l'origine du repère courant. C'est pourquoi on place souvent l'origine au centre de l'objet avant de le faire tourner.

11.4 Démonstration interactive : angle de rotation

Déplacez le curseur. Le point rouge représente le pivot. Observez que l'objet tourne autour du centre et non autour du coin du Canvas.

11.5 Échelle : scale(sx, sy)

ctx.save();

ctx.scale(2, 2);
ctx.fillRect(20, 20, 50, 50);

ctx.restore();

Une échelle de 2,2 agrandit les coordonnées et dimensions dessinées dans les deux directions. Des valeurs différentes peuvent déformer l'objet, tandis qu'une valeur négative peut inverser une direction du repère.

11.6 Exemple complet

ctx.save();

ctx.translate(300, 200);
ctx.rotate(Math.PI / 4);
ctx.scale(2, 2);

ctx.fillStyle = "orange";
ctx.fillRect(-25, -25, 50, 50);

ctx.restore();

Lecture étape par étape :

  1. on sauvegarde l'état ;
  2. on place l'origine à (300,200) ;
  3. on tourne le repère de 45° ;
  4. on agrandit le repère par 2 ;
  5. on dessine un carré centré sur l'origine transformée ;
  6. on restaure l'état précédent.

11.7 Rotation autour du centre d'un objet

function drawRotatedRect(ctx, x, y, w, h, angle) {
  ctx.save();

  // 1. Déplacer l'origine au centre de l'objet
  ctx.translate(x, y);

  // 2. Tourner autour de cette nouvelle origine
  ctx.rotate(angle);

  // 3. Dessiner en plaçant le centre du rectangle sur (0, 0)
  ctx.fillRect(-w / 2, -h / 2, w, h);

  ctx.restore();
}

Cette technique est fondamentale : le rectangle est défini autour de son centre, puis le repère est tourné autour de ce même centre.

11.8 Comparaison visuelle : rotation autour de l'origine vs autour du centre

Rotation autour de (0,0)

L'objet tourne autour de l'origine du repère.

Rotation autour du centre

ctx.translate(cx,cy); ctx.rotate(angle); ctx.translate(-cx,-cy); // dessiner

On place l'origine sur le pivot avant de tourner.

Piège conceptuel :

Si vous faites simplement rotate(angle) sans déplacer l'origine, vous faites tourner l'objet autour de l'origine actuelle du Canvas, pas nécessairement autour de son propre centre.

12. Ordre des opérations et transformations

L'ordre des transformations est crucial. Deux opérations qui utilisent les mêmes méthodes mais dans un ordre différent peuvent produire des résultats différents.

12.1 Translation puis rotation

ctx.translate(400, 250);
ctx.rotate(angle);

Cette organisation est particulièrement pratique pour placer un objet puis le faire tourner autour de la nouvelle origine.

12.2 Pourquoi l'ordre change le résultat

Une transformation modifie le repère utilisé par les transformations suivantes. Ainsi, une translation réalisée après une rotation n'est pas interprétée de la même manière qu'une translation réalisée avant la rotation.

12.3 Comparaison visuelle : l'ordre des transformations compte

translate() puis rotate()

Déplacer puis tourner produit une géométrie spécifique.

rotate() puis translate()

Inverser l'ordre change le résultat : les transformations ne sont généralement pas commutatives.

Règle de raisonnement :

Ne mémorisez pas seulement « translation + rotation ». Demandez-vous toujours : « dans quel repère suis-je au moment où j'applique cette instruction ? »

12.4 Pattern de dessin robuste

ctx.save();

// Transformations propres à l'objet
ctx.translate(x, y);
ctx.rotate(angle);
ctx.scale(sx, sy);

// Styles propres à l'objet
ctx.fillStyle = couleur;

// Dessin local
ctx.fillRect(-w / 2, -h / 2, w, h);

ctx.restore();

Ce modèle permet de définir un objet dans un repère local simple puis de l'insérer dans la scène avec position, rotation et échelle.

12.5 Repère global vs. repère local

RepèreIdéeExemple
GlobalRepère général du Canvas.Coin supérieur gauche = (0,0).
LocalRepère pratique d'un objet après transformation.Centre de la maison = (0,0).

Le repère local rend les objets réutilisables : une même fonction peut dessiner un carré à l'origine, puis translate() permet de placer ce carré n'importe où.

13. Méthode de débogage graphique

Lorsqu'un dessin n'apparaît pas comme prévu, évitez de modifier dix lignes au hasard. Utilisez une procédure systématique.

13.1 Checklist

  1. Le Canvas existe-t-il réellement dans le HTML ?
  2. L'identifiant utilisé par getElementById() est-il correct ?
  3. Le contexte 2d a-t-il été récupéré ?
  4. Le code JavaScript s'exécute-t-il sans erreur dans la console ?
  5. Les coordonnées sont-elles dans une zone visible ?
  6. La largeur et la hauteur sont-elles positives et raisonnables ?
  7. La couleur est-elle visible sur l'arrière-plan ?
  8. Un élément dessiné plus tard recouvre-t-il celui recherché ?
  9. Une transformation précédente est-elle toujours active ?
  10. Un save() / restore() manque-t-il ?
  11. Un chemin précédent est-il involontairement réutilisé parce que beginPath() n'a pas été appelé ?

13.2 Technique : dessiner les repères

ctx.save();

ctx.strokeStyle = "red";
ctx.beginPath();
ctx.moveTo(0, 0);
ctx.lineTo(canvas.width, 0);
ctx.stroke();

ctx.strokeStyle = "blue";
ctx.beginPath();
ctx.moveTo(0, 0);
ctx.lineTo(0, canvas.height);
ctx.stroke();

ctx.restore();

Ajouter temporairement des lignes de repère permet de vérifier l'origine et les axes. C'est particulièrement utile après une transformation.

15. TP 2 — Rosace / mandala avec transformations

Niveau 2 — raisonnement

Dessiner une forme simple répétée autour d'un centre afin d'obtenir une rosace, un mandala ou une composition géométrique.

15.1 Contraintes

  • utiliser translate() ;
  • utiliser rotate() ;
  • utiliser save() / restore() ;
  • répéter la forme au moins 8 fois ;
  • alterner au moins deux couleurs.

15.2 Formule de l'angle

const angle = (2 * Math.PI) / n;

Pour n répétitions régulièrement réparties sur un tour complet, chaque répétition est séparée par 2π / n radians.

15.3 Structure de solution

const n = 12;
const step = (2 * Math.PI) / n;

ctx.save();
ctx.translate(400, 250);

for (let i = 0; i < n; i++) {
  ctx.save();

  ctx.rotate(i * step);

  ctx.fillStyle = i % 2 === 0 ? "royalblue" : "orange";
  ctx.fillRect(80, -15, 100, 30);

  ctx.restore();
}

ctx.restore();

15.4 Analyse du code

  1. Le grand save() protège le repère général.
  2. translate(400,250) place le centre de la rosace.
  3. La boucle produit n copies.
  4. Chaque itération sauvegarde son propre état.
  5. rotate(i * step) donne à chaque copie une orientation différente.
  6. Le rectangle est dessiné à une distance du centre.
  7. Le restore() intérieur empêche la rotation d'une copie de s'accumuler de manière incontrôlée sur les suivantes.

17. Bilan — ce qu'il faut réellement maîtriser

  • Canvas est une surface de dessin contrôlée par JavaScript.
  • ctx est le contexte 2D qui fournit les opérations et possède un état.
  • Le repère par défaut commence en (0,0) en haut à gauche.
  • X augmente vers la droite et Y augmente vers le bas.
  • fillRect() remplit immédiatement un rectangle.
  • strokeRect() trace immédiatement le contour d'un rectangle.
  • clearRect() efface une zone.
  • arc() permet de construire des arcs et cercles.
  • moveTo() déplace le point courant sans tracer ; lineTo() ajoute un segment.
  • beginPath() commence un nouveau chemin.
  • closePath() ferme un chemin.
  • fill() remplit un chemin ; stroke() en dessine le contour.
  • fillStyle et strokeStyle appartiennent à l'état courant du contexte.
  • Les dégradés se construisent avec createLinearGradient() ou createRadialGradient().
  • Le texte se contrôle notamment avec font, textAlign, textBaseline, fillText() et strokeText().
  • translate() modifie l'origine du repère.
  • rotate() tourne le repère ; l'angle est en radians.
  • scale() modifie l'échelle du repère.
  • save()/restore() permettent d'isoler proprement les modifications d'état et de transformation.
  • Le dessin dépend de l'ordre des opérations.
  • Un objet complexe est généralement une composition de primitives.

17.1 Le schéma mental à retenir

1. Je récupère le Canvas et son contexte.
2. Je choisis / comprends mon repère.
3. Je prépare l'état graphique.
4. Je dessine les éléments dans le bon ordre.
5. Pour un objet transformé :
      save()
      → translate()
      → rotate()
      → scale()
      → dessiner dans le repère local
      → restore()
6. Je vérifie visuellement et avec la console.
7. Je transforme les répétitions en fonctions et boucles.

Organiser le projet comme suit :

L'application doit comporter au minimum :

  • une scène graphique complète ;
  • au moins un dégradé ;
  • au moins une forme construite avec un chemin ;
  • du texte ;
  • au moins une transformation ;
  • une utilisation propre de save()/restore() ;

Critère de réussite pédagogique :
